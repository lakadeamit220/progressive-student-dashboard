# Progressive Student Dashboard

A full-stack web application designed to track student progress, recommend next steps, and visualize learning insights.

## Project Overview

The application features a responsive user interface backed by a RESTful API and a MongoDB database. 

- **Student Dashboard**: Displays completed lessons, time spent, and course progress.
- **Visualizations**: Interactive charts to visualize learning insights.
- **Authentication**: JWT-based authentication for secure access.

## Tech Stack

**Frontend**
- **React.js (Vite)**: UI framework.
- **Tailwind CSS**: Utility-first styling.
- **Zustand**: State management.
- **Axios**: HTTP client.
- **Recharts**: Data visualization.

**Backend**
- **Node.js & Express.js**: REST API server.
- **MongoDB & Mongoose**: Database and object data modeling.
- **JWT & bcrypt**: Authentication and password hashing.

## Installation & Setup

### 1. Clone the repository
```bash
git clone https://github.com/lakadeamit220/progressive-student-dashboard.git
cd progressive-student-dashboard
```

### 2. Backend Setup
Navigate to the backend directory and install dependencies:
```bash
cd psd-backend
npm install
```

**Environment Variables:**
Create a `.env` file in the `psd-backend` directory:
```env
PORT=5000
MONGODB_URI="mongodb://127.0.0.1:27017/progressive_student_dashboard"
JWT_SECRET="your_jwt_secret_key"
```

**Initialize Database:**
Run the seed script to populate the database with sample data:
```bash
node seed.js
```

**Start the Server:**
```bash
npm run dev
```
*The backend will be available at `http://localhost:5000`.*

---

### 3. Frontend Setup
Open a new terminal, navigate to the frontend directory, and install dependencies:
```bash
cd psd-frontend
npm install
```

**Start the Client:**
```bash
npm run dev
```
*The frontend will be available at `http://localhost:5173`.*

---

### 4. Testing the Application
Once both servers are running, access the dashboard at `http://localhost:5173`.

## Database Schema Overview

### 1. User
| Field | Type | Description |
| :--- | :--- | :--- |
| `_id` | ObjectId | Unique identifier |
| `name` | String | User's full name |
| `email` | String | Unique email address |
| `passwordHash` | String | Encrypted password |
| `role` | String | User role (`student` or `mentor`) |

### 2. Course
| Field | Type | Description |
| :--- | :--- | :--- |
| `_id` | ObjectId | Unique identifier |
| `title` | String | Course title |
| `description` | String | Course details |
| `totalLessons` | Number | Total number of lessons |

### 3. Lesson
| Field | Type | Description |
| :--- | :--- | :--- |
| `_id` | ObjectId | Unique identifier |
| `courseId` | ObjectId | Reference to Course |
| `title` | String | Lesson title |
| `orderIndex` | Number | Sequence order of the lesson |

### 4. ProgressEvent
| Field | Type | Description |
| :--- | :--- | :--- |
| `_id` | ObjectId | Unique identifier |
| `userId` | ObjectId | Reference to User |
| `courseId` | ObjectId | Reference to Course |
| `lessonId` | ObjectId | Reference to Lesson |
| `timeSpent` | Number | Time spent in minutes |
| `status` | String | `in-progress` or `completed` |

## Development Roadmap

### Phase 1: Environment Setup
- Created the `psd-frontend` folder and set up a new React project using Vite.
- Installed Tailwind CSS v4 and configured it for modern, responsive styling.
- Created the `psd-backend` folder and initialized a Node.js project.
- Installed necessary backend packages like `express`, `mongoose`, `cors`, and `dotenv`.
- Set up the root `README.md` and `.gitignore` files to keep the project clean.

### Phase 2: Database Schemas
- Connected the backend to a local MongoDB database.
- Created the `User` schema to store student and mentor profiles.
- Created the `Course` and `Lesson` schemas to define the learning content.
- Created the `ProgressEvent` schema to track which lessons a student has completed and how much time they spent.

### Phase 3: Database Seeding
- Wrote a `seed.js` script to automatically populate the database so we didn't have to start with an empty dashboard.
- Used authentic Maharashtrian Marathi names (like Aditya Deshmukh and Sneha Kulkarni) for the sample students.
- Generated dummy courses, lessons, and fake progress events to make the dashboard look active.

### Phase 4: Backend API Routes
- Set up a custom JWT (JSON Web Token) middleware to securely protect our API routes.
- Created the Authentication routes (`/api/auth/register`, `/api/auth/login`) so users can sign in safely.
- Built the Course routes to fetch lists of courses and their specific lessons.
- Built the Progress routes (`/api/progress/dashboard`) that calculate the total time spent and count completed lessons for the dashboard cards.

### Phase 5: Frontend State & Auth
- Created an Axios API client that automatically attaches the user's secret token to every backend request.
- Set up a global state store using `Zustand` to easily manage who is logged in across the whole app.
- Built a beautiful, glassmorphic Login page using Tailwind CSS.
- Added "Protected Routes" in React Router so only logged-in users can see the dashboard.

### Phase 6: Student Dashboard UI
- Built the main Dashboard layout, including a sleek left-hand navigation Sidebar.
- Created dynamic Summary Cards that display the real data fetched from our backend (e.g., "Total Time Spent", "Lessons Completed").
- Added glowing backgrounds and icons to make the interface feel premium.

### Phase 7: Visualizations & Features
- Installed `Recharts` to add beautiful data visualizations to the dashboard.
- Created an Area Chart to show the student's learning activity trend over time.
- Created a Donut/Pie Chart to show how the student's completed lessons are distributed across different courses.

### Phase 8: Advanced Features & Role-Based Access Control
- Developed a professional **Landing Page** with marketing copy and call-to-actions.
- Created an interactive **Course Player** allowing students to view lessons and mark them as complete, generating real progress data.
- Built a **Profile & Settings** page allowing users to securely update their email, name, and password.
- Implemented **Role-Based Access Control (RBAC)** to restrict certain API routes based on user roles (`student` vs `mentor`).
- Built a dedicated **Mentor Dashboard** where teachers can view an aggregated data table of all students' learning progress, time spent, and recent activity.
